# What's new

The app's ☰ → What's new shows every `## ` section here, newest first. A blue dot shows on ☰ until a user opens What's new after the top section changes.

Before running **Build apps**, add the version's section at the top, e.g. `## v0.6.4 · Oct 25, 2026`. Build apps uses that section as the release notes, and stops if it's missing.

List only the bigger changes every user would notice. Small or technical changes go under one last line: `- Bug fixes and small improvements.`

## v0.7.0 · Nov 2, 2026

**Team owners:** re-publish the Firebase rules (rules version 10).

- **Fixed performance issues:** smoother loading and scrolling.
- Track how many of a part are damaged or broken.

- Bug fixes and small improvements.
